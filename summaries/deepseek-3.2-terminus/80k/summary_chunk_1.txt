# Parts Unlimited MRP - Architectural Summary (Part 1/3)

## System Overview
Parts Unlimited MRP is a Manufacturing Resource Planning application based on The Phoenix Project, built with open-source technologies including Java, Spring Boot, MongoDB, and Tomcat. The system handles order processing, inventory management, and integration with external systems.

## Core Components and Responsibilities

### 1. Backend Services

#### **OrderService**
- **Primary Responsibility**: Core order management and business logic
- **Technology Stack**: Java, Spring Boot, MongoDB, Gradle
- **Key Features**:
  - Catalog management
  - Quote creation and management
  - Order processing and tracking
  - Dealer management
  - Shipment tracking
  - RESTful API exposure

#### **IntegrationService**
- **Primary Responsibility**: Integration with Parts Unlimited Website
- **Technology Stack**: Java, Spring Boot, Azure Storage Queues
- **Key Features**:
  - Processes orders from website queues
  - Updates product inventory to website
  - Scheduled background tasks for order processing
  - Integration with MRP system via REST API

#### **Clients (Web Frontend)**
- **Primary Responsibility**: User interface for MRP system
- **Technology Stack**: Static HTML/CSS/JavaScript, Tomcat deployment
- **Key Features**:
  - Catalog browsing
  - Order management interface
  - Quote management
  - Dealer information
  - Shipment tracking interface

## API Endpoints and Interfaces

### OrderService REST API

#### Catalog Management
- `GET /catalog` - List all catalog items
- `POST /catalog` - Add new catalog item

#### Dealer Management
- `GET /dealers` - List all dealers
- `POST /dealers` - Add new dealer

#### Quote Management
- `GET /quotes/{id}` - Get specific quote
- `GET /quotes?name={customerName}` - Search quotes by customer
- `POST /quotes` - Create new quote
- `PUT /quotes/{id}` - Update quote
- `DELETE /quotes/{id}` - Delete quote

#### Order Management
- `GET /orders/{id}` - Get specific order
- `GET /orders?dealer={name}&status={status}` - Filter orders
- `POST /orders?fromQuote={quoteId}` - Create order from quote

#### Shipment Management
- `GET /shipments` - List all shipments
- `GET /shipments?status={status}` - Filter by status
- `GET /shipments/{orderId}` - Get shipment details
- `POST /shipments` - Create shipment record
- `PUT /shipments/{orderId}` - Update shipment
- `POST /shipments/{orderId}/events` - Add shipment event

### IntegrationService Interfaces
- **Azure Queue Integration**: Processes messages from `orders` and `product` queues
- **MRP REST API Client**: Communicates with OrderService endpoints
- **Scheduled Tasks**: Background processing at 30-second intervals

## Service Dependencies and Communication Patterns

### Internal Dependencies
1. **IntegrationService → OrderService**: REST API calls for order creation and catalog queries
2. **Clients → OrderService**: All data operations via REST API

### External Dependencies
1. **Azure Storage Queues**: Message passing for order processing
2. **MongoDB**: Primary data storage
3. **Tomcat**: Web application hosting

### Communication Patterns
- **Synchronous**: REST API calls between services
- **Asynchronous**: Azure Queue-based message processing
- **Scheduled**: Background tasks for inventory updates

## Key Business Logic and Algorithms

### Order Processing Flow
1. Website places order → Azure Queue
2. IntegrationService polls queue → Creates Quote in OrderService
3. Quote → Order conversion
4. Order → Shipment creation
5. Inventory updates propagated back to website

### Inventory Management
- Real-time inventory tracking
- Lead time calculations
- Automated stock level updates

### Quote Management
- Quote validation and expiration
- Cost calculation with discounts
- Customer-specific pricing

## Architectural Patterns and Frameworks

### Design Patterns
1. **Repository Pattern**: Data access abstraction in OrderService
2. **Service Layer**: Business logic separation
3. **RESTful API**: Resource-oriented interface design
4. **Message Queue Pattern**: Asynchronous processing
5. **Scheduled Task Pattern**: Background job processing

### Frameworks and Libraries
- **Spring Boot**: Application framework
- **Spring Web**: REST API development
- **Azure Storage SDK**: Queue integration
- **Jackson**: JSON serialization/deserialization
- **MongoDB Java Driver**: Database connectivity
- **Gradle**: Build automation

### Microservice Characteristics
- **Loose Coupling**: Services communicate via well-defined APIs
- **Single Responsibility**: Each service has distinct business domain
- **Independent Deployment**: Services can be deployed separately
- **Technology Diversity**: Potential for different tech stacks per service

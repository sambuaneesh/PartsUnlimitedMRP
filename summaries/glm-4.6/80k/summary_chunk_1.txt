
# Comprehensive Architectural Summary: Parts Unlimited MRP (Part 1)

## System Overview
Parts Unlimited MRP is a fictional Manufacturing Resource Planning (MRP) application designed for DevOps training, based on "Project Unicorn" from The Phoenix Project. The system demonstrates a microservices architecture using open-source technologies including Linux, Java, Apache Tomcat, and MongoDB.

## Core Components

### 1. Frontend Web Service
- **Location**: `src/Clients/Web/`
- **Technology Stack**: Static HTML/CSS/JavaScript on Apache Tomcat 7
- **Primary Port**: 9080 (customized from default 8080)
- **Responsibilities**:
  - Provides web-based user interface for MRP operations
  - Handles user interactions for catalog browsing, order management, quote creation
- **Key Pages/Modules**:
  - **Main**: Primary dashboard (`main/main.html`, `main.js`)
  - **Catalog**: Product browsing and management (`catalog/`)
  - **Dealers**: Dealer management (`dealers/`)
  - **Orders**: Order creation and tracking (`orders/`)
  - **Quotes**: Quote generation and management (`quotes/`)
  - **Deliveries**: Shipment tracking (`deliveries/`)
  - **Order Events**: Event tracking (`orderevents/`)
- **API Communication**: Makes REST calls to Order Service at port 8080
- **Configuration**: Server configuration in `js/serverconfig.js`

### 2. Order Service Backend
- **Location**: `src/Backend/OrderService/`
- **Technology Stack**: Java 8 + Spring Boot framework
- **Primary Port**: 8080
- **Build System**: Gradle
- **Responsibilities**:
  - Core business logic for MRP operations
  - Provides RESTful APIs for frontend and external integrations
  - Manages data persistence via MongoDB
- **API Endpoints**:
  - **Catalog Management**:
    - `GET /catalog` - List all catalog items
    - `POST /catalog` - Add new catalog item
    - `GET /catalog/{sku}` - Get specific item
  - **Dealer Management**:
    - `GET /dealers` - List all dealers
    - `POST /dealers` - Add new dealer
  - **Order Management**:
    - `GET /orders` - List orders
    - `POST /orders?fromQuote={quoteId}` - Create order from quote
    - `GET /orders/{orderId}` - Get specific order
    - `PUT /orders/{orderId}` - Update order
  - **Quote Management**:
    - `GET /quotes` - List quotes
    - `POST /quotes` - Create new quote
    - `GET /quotes/{quoteId}` - Get specific quote
    - `PUT /quotes/{quoteId}` - Update quote
    - `DELETE /quotes/{quoteId}` - Delete quote
  - **Shipment Management**:
    - `GET /shipments` - List shipments
    - `POST /shipments` - Create new shipment
    - `GET /shipments/{orderId}` - Get shipment for order
    - `PUT /shipments/{orderId}` - Update shipment
    - `POST /shipments/{orderId}/events` - Add shipment event

#### Data Models
- **CatalogItem**: skuNumber, description, unit, price, inventory, leadTime
- **DealerInfo**: name, address, email, phone
- **Order**: orderId, quoteId, orderDate, status, events[]
- **Quote**: quoteId, customerName, dealerName, validUntil, items[], cost details
- **ShipmentRecord**: orderId, deliveryAddress, contact info, events[]

#### Repository Pattern
- **Interface-based Design**: Separate repository interfaces
- **Implementations**:
  - **MongoDB Repositories** (`repositories/mongodb/`): Production implementation
  - **Mock Repositories** (`repositories/mock/`): Testing implementation
- **Repository Types**:
  - `CatalogItemsRepository`
  - `DealersRepository`
  - `OrderRepository`
  - `QuoteRepository`
  - `ShipmentRepository`

### 3. Integration Service
- **Location**: `src/Backend/IntegrationService/`
- **Technology Stack**: Java 8 + Spring Boot + Azure Storage SDK
- **Responsibilities**:
  - Bridges external MRP system with internal Order Service
  - Handles asynchronous communication via Azure Queue Storage
  - Scheduled tasks for system synchronization
- **Key Components**:
  - **MrpConnectService**: REST client for external MRP system
  - **QueueService**: Wrapper for Azure Queue operations
  - **QueueFactory**: Manages queue connection pooling
  - **Scheduled Tasks**:
    - `CreateOrderProcessTask`: Processes new orders from queue (30s interval)
    - `UpdateProductProcessTask`: Syncs catalog updates (30s interval)

#### Communication Patterns
- **External MRP System**: REST API calls to host defined by `mrp.endpoint`
- **Queue-based Messaging**: 
  - Orders Queue (`azure.storage.queue.orders`)
  - Inventory Queue (`azure.storage.queue.inventory`)
- **Configuration**: Managed via `application.properties`

### 4. Database Layer
- **Technology**: MongoDB
- **Database Name**: `ordering`
- **Key Collections**:
  - `catalog`: Product catalog with SKU, description, price, inventory, leadTime
  - `dealers`: Dealer information (single document in sample data)
  - `quotes`: Quote documents with items, pricing, validity
  - `orders`: Order tracking with status and events
  - `shipments`: Delivery information with addresses and events
- **Initial Data**: Populated via `MongoRecords.js` script

## Deployment Architecture

### 1. Containerization
- **Docker Support**: Complete containerization setup in `deploy/docker/`
- **Multi-Container Design**:
  - **Database Container**: MongoDB with exposed ports 27017/28017
  - **Order Service Container**: Java application on port 8080
  - **Frontend Container**: Tomcat serving static content on port 80
- **Networking**: Containers linked via Docker networking
- **Build Scripts**: `BuildAndRun.sh` and `StopAndRemove.sh`

### 2. Azure Deployment
- **ARM Templates**: Comprehensive templates in `deploy/azurestack/instances/`
- **Deployment Options**:
  - **Standalone MRP**: Ubuntu VM with full stack
  - **Jenkins Integration**: Separate Jenkins master + MRP VM
  - **Chef Integration**: Chef server + node deployment
  - **Puppet Integration**: Puppet Enterprise setup
  - **SSH-based Deployment**: Key-based authentication option
- **Network Security**: NSG rules for SSH (22), HTTP (80/443), Application (9080, 8080)

### 3. Configuration Management
#### Chef
- **Cookbooks**: Located in `Labfiles/.../DeployusingChef/final/default.rb`
- **Recipes**:
  - Java 8 installation
  - MongoDB setup and data population
  - Tomcat 7 configuration
  - Application deployment
  - Service management

#### Puppet
- **Modules**: In `Labfiles/.../Puppet/final/init.pp`
- **Classes**:
  - `configuremongodb`: MongoDB setup
  - `configurejava`: Java installation
  - `configuretomcat`: Tomcat configuration
  - `deploywar`: Application deployment
  - `orderingservice`: Service management

### 4. CI/CD Pipelines
#### Jenkins
- **Pipeline Configuration**: Automated build and deploy scripts
- **Integration**: Azure VM templates for Jenkins + MRP deployment
- **Build Steps**: Gradle build → Test → Package → Deploy

#### Travis CI
- **Configuration**: `.travis.yml` for Java projects
- **Build Matrix**: Oracle JDK 8
- **Test Execution**: Unit tests run automatically

## Architectural Patterns

### Repository Pattern
- **Data Access Abstraction**: Interface-based repository design
- **Multiple Implementations**: Mock for testing, MongoDB for production
- **Factory Pattern**: Dynamic repository selection

### Scheduled Tasks
- **Background Processing**: Spring's `@Scheduled` annotation
- **Configurable Intervals**: 30-second intervals for queue processing
- **Error Handling**: Comprehensive exception management

### Microservice Characteristics
- **Single Responsibility**: Each service has focused purpose
- **Data Ownership**: Clear data domain boundaries
- **Independent Deployment**: Services deployable separately
- **Technology Diversity**: Different stacks per service needs

This architecture provides a solid foundation for microservice decomposition, with clear service boundaries, standardized communication patterns, and comprehensive deployment options supporting various infrastructure scenarios.

# Parts Unlimited MRP - Architectural Summary (Part 1)

## 1. System Overview
Parts Unlimited MRP is a Java-based Manufacturing Resource Planning application using a monolithic architecture with three primary layers:
- **Frontend**: Static web client (HTML/CSS/JavaScript) served by Apache Tomcat
- **Backend**: Spring Boot Java services (OrderService, IntegrationService)
- **Database**: MongoDB with collections for catalog, dealers, quotes, orders, and shipments

## 2. Core Components

### Frontend (`src/Clients/`)
- **Technology**: Static HTML5/CSS3/JavaScript
- **Deployment**: WAR file deployed to Tomcat
- **Key Pages**:
  - Catalog management
  - Order processing
  - Quote generation
  - Dealer management
  - Shipment tracking
- **API Integration**: Consumes RESTful endpoints from backend services

### Backend Services (`src/Backend/`)

#### OrderService (`/OrderService/`)
- **Framework**: Spring Boot (Java)
- **Port**: 8080
- **Key Controllers**:
  - `CatalogController`: `/api/catalog` - Product catalog operations
  - `OrderController`: `/api/orders` - Order lifecycle management
  - `QuoteController`: `/api/quotes` - Quote generation/expiry
  - `DealerController`: `/api/dealers` - Dealer information
  - `ShipmentController`: `/api/shipments` - Delivery tracking
- **Data Layer**: MongoDB repositories with retry logic
- **Business Logic**:
  - Order status workflow (Created → DeliveryConfirmed)
  - Quote expiry validation
  - Inventory level checks
  - Dealer commission calculations

#### IntegrationService (`/IntegrationService/`)
- **Framework**: Spring Boot (Java)
- **Purpose**: External system integration (Parts Unlimited Website)
- **Key Features**:
  - Scheduled tasks for order processing
  - Queue-based communication (Azure Service Bus)
  - Message transformation (MRP ↔ Website formats)
- **Scheduled Tasks**:
  - `CreateOrderProcessTask`: Process incoming orders
  - `UpdateProductProcessTask`: Sync product updates

  - Configures Tomcat (port 9080)

- **Docker Support** (`deploy/docker/`):
  - Multi-container setup:
    ```bash

    docker run -p 8080:8080 --link db:mongo mypartsunlimitedmrp/order
    docker run -p 80:8080 mypartsunlimitedmrp/web
    ```

### CI/CD Integration

  - Automated deployment pipeline
  - VM provisioning via Azure templates

## 6. Key Architectural Patterns

### Repository Pattern
```java
// Example from MongoOrderRepository
@Repository
public class MongoOrderRepository implements OrderRepository {
  @Autowired
  private MongoOperationsWithRetry mongo;
  
  public Order getOrder(String orderId) {
    return mongo.findOne(query(where("orderId").is(orderId)), Order.class);
  }
}
```

### Configuration Management
- **Properties**: Centralized in `application.properties`
- **Environment Variables**: Database URLs, queue connections
- **Feature Flags**: Mock vs. MongoDB repositories

### Error Handling
- Custom exceptions (`BadRequestException`, `ConflictingRequestException`)
- Global filters (`SimpleCORSFilter`, `AppInsightsFilter`)

## 7. Business Logic Algorithms

### Order Processing Workflow
1. **Quote Generation**:
   - Validate dealer
   - Check inventory levels
   - Apply discount rules
   - Set expiry (30 days default)

2. **Order Creation**:
   - Validate quote still valid
   - Reserve inventory
   - Generate shipment record
   - Update order status

3. **Shipment Tracking**:
   - Event-driven status updates
   - Delivery confirmation logic
   - Notification triggers

## 8. Security & Observability
- **CORS Config**: Cross-origin request handling
- **App Insights**: Application monitoring
- **Logging**: Structured logging with request tracking
- **Validation**: Input sanitization in controllers

## 9. Microservice Decomposition Insights

### Natural Service Boundaries Identified:
1. **Catalog Service**: Product management
2. **Order Service**: Order lifecycle
3. **Quote Service**: Quote generation/expiry
4. **Dealer Service**: Dealer information
5. **Shipment Service**: Delivery tracking
6. **Integration Service**: External system bridge

### Critical Dependencies:
- **MongoDB**: All services currently share a single database
- **Tomcat**: Frontend tightly coupled to OrderService
- **Shared Models**: `integration/models` and `ordering/models` have significant overlap

### Key Integration Points:
- Queue-based messaging between services
- RESTful APIs for synchronous calls
- Scheduled tasks for data synchronization

  - **Internal Load Balancer (`mySlb`)**:

## Architectural Summary: OrderService & Client Components (Part 3)

### Core Models & Business Logic
**Quote Management**  
- `Quote`: Central entity with quoteId, customer/dealer names, `QuoteItemInfo` list, cost/discount, and delivery location  
- Validation: Enforces non-null `dealerName` and `customerName`  
- `QuoteItemInfo`: Line items with SKU and amount; supports sorting  
- Lifecycle: Created from customer/dealer data; generates orders

**Order Processing**  
- `Order`: Linked to quotes via `quoteId`; tracks status (`Created`→`Shipped`) and events  
- Order Updates: Supports status changes and event logging (`OrderEventInfo`)  
- Creation Flow: Orders derive from validated quotes

**Shipment Tracking**  
- `ShipmentRecord`: One-to-one with orders; stores delivery address, contacts, and events  
- `ShipmentEventInfo`: Timestamped comments (e.g., "Truck dispatched")  
- Validation: Requires `orderId` and non-empty comments

### Data Persistence Architecture
**Repository Pattern**  
- **Interfaces**: `CatalogItemsRepository`, `DealersRepository`, `OrderRepository`, `QuoteRepository`, `ShipmentRepository`  
- **Dual Storage**:  
  - **Mock Repositories** (`Mock*Repository.java`): In-memory storage for testing  
  - **MongoDB Repositories** (`Mongo*Repository.java`): Production persistence with retry logic  
- **Factory Switch**: `RepositoryFactory` dynamically selects storage type via configuration (`ordering.storage: memory/mongodb`)  

**MongoDB Implementation**  
- Spring Data MongoDB with custom `MongoOperationsWithRetry` for transient fault handling  
- Telemetry integration for monitoring DB operations  
- Document models (e.g., `MongoCatalogItem`) map to domain objects  

### API Design
**REST Endpoints**  
| Resource    | Operations                         | Key Features                     |
|-------------|-----------------------------------|----------------------------------|
| /quotes     | CRUD, search by customer/dealer    | Quote-to-Order conversion        |
| /orders     | CRUD, status updates, event add    | Dealer-filtered queries         |
| /shipments  | CRUD, event logging               | Status-based retrieval           |
| /catalog    | CRUD, SKU search                  | Inventory/price management      |
| /dealers    | CRUD                              | Auto-dealer creation on quotes  |

**Response Semantics**  
- `201 CREATED` on successful resource creation  
- `409 CONFLICT` for duplicate resources (e.g., duplicate orders from quotes)  
- ETags for optimistic concurrency control  

### Client Architecture (Web Frontend)
**WinJS Application**  
- **Navigation**: SPA with sections for Dealers, Quotes, Orders, Deliveries, Catalog, Settings  
- **Data Layer** (`data.js`): RESTful HTTP calls to backend using WinJS.xhr  
- **CRUD Operations**:  
  - Binding lists for views (`WinJS.Binding.List`)  
  - Dual-panel UI (list view + edit form)  
  - Promises for async operations  

**Edit Tools** (`edittools.js`)  
- Reusable control for Save/Delete/Add actions  
- WinJS-based custom buttons with SVG icons  

### Configuration & Deployment
**Backend**  
- **Spring Boot**: Configured via `application.properties`  
- **Database Switch**: `ordering.storage` property selects mock/MongoDB  
- **Telemetry**: Application Insights integration  
- **Ports**: Main (8080) + Management (8081)  

**Client**  
- **Gradle Build**: Generates `mrp.war` for Tomcat deployment  
- **Static Assets**: WinJS framework, Google Maps API, custom CSS/JS  

### Testing Strategy
**Unit Tests**  
- Repository test inheritance (`*RepositoryTest`) with mock/Mongo implementations  
- `ConfigurationRule` enforces Spring context during tests  
- Test data factories (e.g., `createDealer()`)  

**Integration Tests**  
- `@Category(IntegrationTests.class)` for MongoDB-specific tests  
- Repository reset between tests (`TestPath.reset()`)  

### Architectural Patterns
- **Repository Pattern**: Abstraction for data access  
- **Factory Pattern**: Dynamic storage selection  
- **Template Method**: Base test classes with shared setup  
- **Command Pattern**: Edit tool actions  
- **Event-Driven**: Order status updates trigger event logging  

### Key Dependencies
- **Backend**: Spring Data MongoDB, Application Insights, JUnit  
- **Frontend**: WinJS, Google Maps API, Gradle  

### Service Interactions
```mermaid
graph LR
  A[Quote] -->|Generates| B[Order]
  B -->|Triggers| C[Shipment]
  D[Catalog] -->|Populates| A
  E[Dealer] -->|Validates| A
```

### Decomposition Insights
**Microservice Candidates**:  
1. **Quote Service**: Quote lifecycle, validation, item management  
2. **Order Service**: Order creation, status tracking, event logging  
3. **Shipment Service**: Delivery tracking, event management  
4. **Catalog Service**: Product data, SKU management  
5. **Dealer Service**: Dealer information, address validation  

**Critical Couplings**:  
- Order creation requires Quote validation  
- Shipment creation depends on Order existence  
- Catalog lookup needed for QuoteItemInfo validation  

**Optimizations Needed**:  
- Replace shared `RepositoryFactory` with service-specific config  
- Implement inter-service communication (REST/events) for cross-domain operations  
- Isolate database schemas per service in MongoDB

## Architectural Summary: Parts Unlimited MRP System (Frontend Web Client)

### **1. Application Architecture**
- **Framework**: Windows Store App using WinJS (Windows JavaScript Library)
- **Pattern**: Single Page Application (SPA) with client-side navigation
- **Architecture Style**: Component-based MVVM (Model-View-ViewModel) with data binding
- **Platform**: Windows 8/10 Store Application

### **2. Core Components**

#### **Navigation System**
- **File**: `navigator.js`
- **Component**: `PageControlNavigator`
- **Responsibilities**: 
  - Manages page lifecycle and transitions
  - Handles navigation history
  - Implements responsive layout updates
  - Disposes previous page controls

#### **Application Shell**
- **File**: `default.js`
- **Responsibilities**:
  - Application initialization and activation handling
  - Global error handling
  - Progress indicator management
  - Common dialog system (confirmation, error reporting)

#### **Data Binding Infrastructure**
- **Custom Binding Mode**: `Binding.Mode.twoway` implementation
- **Template System**: WinJS.Binding.Template for list rendering
- **Data Sources**: WinJS.Binding.List for observable collections

### **3. Business Modules (Pages)**

#### **Main Dashboard**
- **Path**: `pages/main/`
- **Features**: Launch tiles for navigation to business modules
- **Navigation Pattern**: Tile-based UI with click handlers

#### **Dealers Management**
- **Path**: `pages/dealers/`
- **CRUD Operations**: Create, read, update, delete dealers
- **Features**: Google Maps address autocomplete integration
- **Data Fields**: Name, contact, address, email, phone

#### **Quotes Management**
- **Path**: `pages/quotes/`
- **Features**: 
  - Quote creation and editing
  - Integration with extras management
  - Navigation to orders from quotes
- **Data Fields**: Dealer, customer, dimensions, pricing, terms

#### **Orders Management**
- **Path**: `pages/orders/`
- **Features**:
  - Order status tracking (Created → Installed workflow)
  - Quote-to-order conversion
  - Navigation to deliveries from orders
- **Status States**: Created, Confirmed, Started, Built, DeliveryConfirmed, Shipped, Delivered, Installed

#### **Deliveries Management**
- **Path**: `pages/deliveries/`
- **Features**:
  - Delivery scheduling and tracking
  - Order-to-delivery conversion
  - Delivery event management
- **Data Fields**: Delivery address, contact phones, delivery date

#### **Product Catalog**
- **Path**: `pages/catalog/`
- **Features**: Product SKUs management
- **Data Fields**: SKU number, description, unit, unit price

#### **Extras Management**
- **Path**: `pages/extras/`
- **Features**: Additional items management for quotes/orders
- **Pattern**: Modal popup integration from parent entities

#### **Order Events**
- **Path**: `pages/orderevents/`
- **Features**: Event tracking for orders/deliveries
- **Data Fields**: Date, comments

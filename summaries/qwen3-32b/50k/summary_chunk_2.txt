### **3. Microservices Architecture**
#### **IntegrationService (Java Spring Boot)**
- **Purpose:** Handles background integration processes (e.g., syncing orders, inventory, and shipments between website and MRP system).  
- **Key Responsibilities:**  
  1. **Order Processing:**  
     - Periodically polls Azure queues for incoming orders.  
     - Creates quotes, orders, and shipments via HTTP to the MRP system.  
  2. **Inventory Synchronization:**  
     - Fetches catalog inventory updates from MRP system.  
     - Posts updates to Azure queues.  
- **Scheduled Tasks:**  
  - `CreateOrderProcessTask`: Polls MRP endpoint every 30 seconds (value from `application.properties`).  
  - `UpdateProductProcessTask`: Syncs product inventory with MRP every 30 seconds.  
  - **Threading:** Uses thread-safe maps for Azure queue caching.
- **Key Dependencies:**  
  - MRP system (REST API, endpoint: `mrp.endpoint` in `application.properties`)  
  - Azure Storage Queues (config key: `azure.storage.connectionstring`)  
- **Data Models:**  
  - `OrderMessage`: Represents incoming orders from the website.  
    - Fields: `customerName`, `address`, `phone`, `SKU` items, delivery details.  
  - `Quote`: Tracks quote details (dealer info, inventory, cost).  
    - Dependency: `QuoteItemInfo` (maps website `OrderItem` to MRP).  
  - `ShipmentRecord`: Tracks delivery logistics (address, contact, events).  
    - Events: `ShipmentEventInfo` with date and comments.  

#### **OrderService (Java Spring Boot)**
- **Purpose:** Manages order lifecycle (quotes, orders, shipments) via a REST API.  
- **Core API Endpoints:**  
  - **Quotes:**  
    - `GET /quotes/{quoteId}`  
    - `POST /quotes` (creates quote from `quote1.json`)  
    - `PUT /quotes/{quoteId}` (updates quote details)  
    - `DELETE /quotes/{quoteId}`  
  - **Orders:**  
    - `POST /orders?fromQuote={quoteId}` (converts quote to order)  
    - `GET /orders/{orderId}`  
    - `PUT /orders/{orderId}` (updates order)  
    - `GET /orders?dealer={name}&status={statusName}` (filters orders by dealer/status)  
    - `POST /orders/{orderId}/events` (adds order events)  
  - **Shipments:**  
    - `POST /shipments` (creates shipment)  
    - `GET /shipments/{orderId}`  
    - `POST /shipments/{orderId}/events` (adds shipment events)  
- **Key Dependencies:**  
  - **MRP System:** Calls `.mrp.war` endpoints (e.g., `/orders`, `/shipments`) to create/upd orders.  
  - **Azure Queues:** Deploys via `QueueService` and `QueueFactory` for message-passing.  

- **Repositories:**  
  - Implements storage abstractions (`mongodb`, `postgresql`) via `RepositoryFactory`.  
  - **Database Schemas:**  
    - **Quotes:**  
      - `quote_id` (PK)  
      - `customer_name`, `dealer_name` (FK to Dealers)  
    - **Orders:**  
      - `order_id` (PK)  
      - `quote_id` (FK to Quotes)  
    - **Shipments:**  
      - `order_id` (PK)  
      - References `Orders.order_id` and links to `DeliveryAddress`, `PhoneInfo`.  
    - **Legacy:** PostgreSQL schema (`schema.psql`) for order lifecycle tracking.  

- **External Systems Integration:**  
  - **Azure Storage:**  
    - Uses `QueueService` to serialize/deserialize JSON payloads (e.g., `OrderMessage`, `ProductMessage`).  
    - Queues:  
      - Orders Queue (`azure.storage.queue.orders`)  
      - Inventory Queue (`azure.storage.queue.inventory`)  
  - **Application Insights:**  
    - Instruments HTTP requests and exceptions (via `AppInsightsFilter`).  
    - Metrics: Response time, error rates, build information.

### **4. Service Communication Patterns**
- **IntegrationService → MRP System (REST API):**  
  - Uses `MrpConnectService` to call MRP endpoints (e.g., `/order`, `/ships`).  
  - **Key Flows:**  
    - Order creation: `POST /orders` with customer name and inventory.  
    - Product updates: `POST /product` with inventory and lead time.  
- **IntegrationService ↔ OrderService (Event Queue):**  
  - Orders placed in `orders` queue are processed by IntegrationService.  
  - Inventory updates (from `product` queue) are pushed back to website via IntegrationService.  
- **OrderService ↔ Azure Queues:**  
  - **Inbound:** Pull tasks from `orders` queue for processing.  
  - **Outbound:** Push `product` updates to Azure Queue for IntegrationService to consume.

### **7. Business Logic**
- **Integration Logic:**  
  - **Scheduled Tasks:**  
    - **Order Creation:** Waits 30 seconds between polls, creates orders in MRP if they meet criteria.  
    - **Inventory Sync:** Fetches new inventory from MRP, pushes to website queue (`product` queue).  
- **Quote Lifecycle:**  
  - Quotes transition through `OrderService` from creation to delivery confirmation.  
  - Requires dealer existence (via REST API checks).  
- **Shipping Logic:**  
  - Ships `Shipments` after 14 days (statically configured in models).  
  - Uses `DeliveryAddress` and `PhoneInfo` to track delivery info.

### **8. Security & Compliance**
- **SSH Restrictions:** Only allows TCP port 22 access in NSG and VM configuration.  
- **Permissions:**  
  - Apache/Nginx directories are set to `0777` for Ansible-automated access.  
  - System user `adminUsername` is non-root with password-based access (should be updated for hardened auth).  
- **Queue Security:**  
  - Azure queues use storage account keys (hardcoded in `application.properties`).  
  - Needs reencryption using Key Vault for production.

### **9. Limitations for Microservice Decomposition**
- **Monolithic Configuration:** `application.properties` handles both OrderService and IntegrationService logic; these services should be separated with distinct config files.  
- **Tight Dependency on MRP:** IntegrationService requires MRP REST endpoints; should be abstracted using APIs.  
- **Shared Storage Queue:** Both services directly interact with Azure storage queues; decouple with a dedicated message queue microservice.  
- **Local Build Scripts:** Need containerization (Docker, HELM) or cloud orchestration tools to isolate microservices.
